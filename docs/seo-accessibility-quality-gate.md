# Xpress Your Royalty — SEO, Accessibility & Launch Quality Gate

## Objective
The enterprise redesign is not complete when it looks polished. It is complete when visitors can find it, understand it, navigate it, use it on mobile and assistive technology, and reach the inquiry path reliably.

## Heading rules
- One meaningful H1 per page.
- H2s organize major sections.
- H3s sit beneath relevant H2s; do not choose headings solely for visual size.
- Do not use images of text for important headings.

## Image rules
- Descriptive alt text for meaningful images.
- Decorative images should not create noisy repetitive announcements.
- File/media names should be useful when practical.
- Compress large originals and use Wix responsive delivery.
- Validate crop/focal point on desktop and mobile.
- Avoid text embedded into photographs when equivalent HTML text can be used.

Example alt text:
`Burgundy and gold draped event backdrop with layered fabric and illuminated focal area installed by Xpress Your Royalty.`

## Accessibility gate
- Keyboard navigation reaches all interactive controls.
- Visible focus indicator remains present.
- Color contrast supports readable body text and buttons.
- Link purpose is understandable from text/context.
- Forms have visible labels and useful errors.
- Mobile controls are comfortably tappable.
- No essential information exists only on hover.
- Motion is restrained; reduced-motion preferences are respected where custom code controls animation.
- Autoplay video, if used, is muted and nonessential; provide a static fallback.
- Page zoom/reflow does not destroy essential content.

## Performance gate
- Hero asset optimized; avoid loading oversized video unless it clearly earns its cost.
- Lazy-load below-fold galleries where Wix supports it.
- Limit decorative animations and third-party embeds.
- Avoid hotlinked social images for core portfolio content.
- Review mobile performance after adding galleries.
- Remove unused or duplicate visual components where practical.

## Local discovery
Naturally describe the real service geography: Delaware, Pennsylvania, New Jersey and Maryland where project scope/logistics permit. Use city/location references on portfolio stories only when accurate. Do not create doorway pages or repetitive city pages without meaningful local content.

## Structured content opportunities
Where Wix/platform configuration supports it, evaluate:
- Organization/LocalBusiness schema with accurate business data.
- Service information.
- Breadcrumbs on deeper pages.
- FAQ schema only when the FAQ is visible and eligible under current search-engine rules.

Do not fabricate aggregate ratings/reviews in structured data.

## Conversion tracking
Track, where available and privacy-appropriate:
- Primary HoneyBook inquiry CTA clicks.
- Consultation CTA clicks.
- Portfolio -> inquiry transitions.
- Draping page -> inquiry transitions.
- Rental page -> inquiry transitions.
- Contact email/phone actions where useful.

Define one primary conversion: a qualified event inquiry/consultation action.

## Content integrity gate
Before launch verify:
- info@xpressyourroyalty.com is used where approved.
- Phone number and service area are current.
- No unverified testimonials.
- No unsupported awards, metrics or superlatives.
- No `Coming soon` placeholders that make the site look unfinished.
- Rental policies do not contradict the signed agreement.
- Wedding language does not over-position large-wedding coordination.
- Social/client imagery is approved for public marketing use.
- Copyright/current business information is updated.

## Functional gate
- Every primary CTA reaches the intended HoneyBook path.
- Navigation has no dead links.
- Portfolio cards open correctly.
- Forms work on iPhone/Android-sized screens.
- Email and phone links are correct.
- Back button/navigation behavior is sensible.
- 404/not-found behavior is acceptable.
- External links open as intended.

## Final pre-publish checklist
1. Desktop visual review.
2. Mobile visual review.
3. Keyboard accessibility pass.
4. Contact/business-data pass.
5. CTA/HoneyBook pass.
6. Image/alt-text pass.
7. Testimonial/claim verification pass.
8. SEO title/description pass.
9. Performance sanity check.
10. Analytics/conversion verification.
11. Publish only after the above are acceptable.

## Post-launch review
Within the first operating period after launch, review actual visitor behavior and inquiry quality. Improve copy/CTA placement based on evidence rather than adding visual effects by default.
